## 0. この案の前提 — **読み手と場所で書き分ける**

App Store の1画面には、性質のまったく違う2種類の読み手が同居している。
同じ文を使い回すと、どちらにも刺さらない（`.secretary/Preferences/copywriting-audience.md`）。

| 場所 | 読み手 | 書くこと |
|---|---|---|
| アプリ名／**サブタイトル**／スクショ1枚目／プロモーションテキストの1文目 | **初見の人**（検索結果を上から流し見ている） | その人が**もう持っている悩み**。製品を知らなくても意味が通る言葉 |
| 説明文の本文／スクショ3枚目以降／レビュー返信 | **比較検討中の人**（他アプリと見比べている） | **他と何が違うか**。競合の失点を踏まえた差別化 |

### 前の案の失敗（2026-08-01・大翔の指摘）

サブタイトルを「**AIが勝手に分量を変えない**」にしていた。
根拠（下の★1レビュー）は正しいが、大翔の反応は

> 「全然日本語の意味がわかんないっす。どういうことこれ？」

**否定形は、否定される対象を知らない人には空振りする。**
初見の人は「AIが分量を勝手に変える」という現象自体を知らない。
→ **差別化は捨てず、説明文の本文（＝比較検討層の場所）へ下ろした。**

### 根拠にした一次情報

競合の課金者レビュー：

| 競合 | 規模 | ★1で繰り返される不満 |
|---|---|---|
| CookGo | 10万DL・9,015件 | 「砂糖大さじ1→砂糖小さじ1のように致命的な間違いが当たり前。ほぼ全てのレシピに大きな間違いがあります」 |
| pecco | 50万DL・2,206件 | 「冷蔵庫にある物を入力して検索したのに、ない物でのレシピしか出てこなかった。そく削除した」 |
| クラシル | 757,913件 | 「Web版では人数で調節できるのにアプリ版は無い。プレミアム解約、アンインストール」 |
| DELISH KITCHEN | 500,532件 | 人数変更は公式に「提供しておりません」 |

不満の中身は3つとも CookSync の実装で既に埋まっている（追加開発ゼロで言える）。
ただしこれは**すでに痛い目を見た人にしか通じない話**なので、置き場所は説明文の本文。

生活者調査：

- 夕食の悩み1位＝「**献立を考えること」65.8%**（レパートリー不足44.1%・後片付け40.8%を上回る）
- 献立を考えるタイミング＝「**帰宅途中50.4%**」「**買い物中50.1%**」
- 家庭の食品ロスのうち**期限切れ廃棄は18%だけ**（過剰除去55%・食べ残し27%）

→ **初見向けの一等地は「今日なに作るか決まらない」（65.8%）で取る。**

### 書いてはいけないこと（調査で潰れた／未実装）

- ❌「AIが勝手に分量を変えない」を**サブタイトルに置く** … 上記。説明文の本文へ。
- ❌「動画URLからレシピ」を**単独の看板にする** … CookGo が10万DLで先行。機能として並べるのは可。
- ❌「冷蔵庫にあるもので献立」を**pecco と同じ言い回しで**看板にする … サブタイトルで占有済み。真正面は劣化版に見える。語をずらす（「家にあるもの」）か、「本当に守る」という限定をつける。
- ❌「レシートを撮るだけ」 … **レシート読み取りは未実装**（冷蔵庫写真からの食材認識はある）。書かない。
- ❌ 主訴求を食品ロスにする … 食品ロスは**10月（食品ロス削減月間）のPRフック専用**に回す。

## 1. アプリ名（30字以内）

**採用案**

```
CookSync 冷蔵庫レシピ・献立AI
```

（20字。半角スペース1つ込み）

- 前半＝ブランド、後半＝**検索される名詞**（冷蔵庫／レシピ／献立／AI）。
- 名前欄は「探している人に見つけてもらう」ための欄。ここで訴求を語ると検索語が入らなくなる。
- 悩みの言葉はサブタイトルで言う。

**代替案**

| 案 | 字数 | メモ |
|---|---|---|
| `CookSync 冷蔵庫の食材からレシピ` | 20 | 「献立」「AI」が落ちる |
| `CookSync 献立AI・冷蔵庫の在庫管理` | 22 | 「レシピ」が落ちる |
| `CookSync 冷蔵庫レシピ・買い物リスト` | 22 | 買い物リスト訴求を名前に上げる場合 |

## 2. サブタイトル（30字以内）— **初見向け**

**採用案**

```
今日なに作るか、家にあるもので決まる
```

（18字）

**選定理由**

- 夕食の悩み1位（**65.8%**）そのもの。**CookSync を今日はじめて見た人が読んで、意味が分かる。**
- 肯定形。「決まる」で読後の状態（結果）まで言い切っている。
- 「**家にあるもの**」は pecco のサブタイトル「冷蔵庫にあるもので最適な献立レシピを提案し賞味期限も管理」と語をずらすため。同じ「冷蔵庫にあるもので」を真正面から言うと劣化版に見える。
- 名前欄が「冷蔵庫／レシピ／献立／AI」を持っているので、サブタイトルは検索語を稼ぐ必要がない。悩みの言葉に全振りできる。
- アプリ内の `APP_TAGLINE`（ホーム画面のロゴ下・PWA manifest）と**同じ文にしてある**。ストアで刺さった言葉が、開いた直後の画面にもある状態にする。

**代替案**

| 案 | 字数 | 使いどころ |
|---|---|---|
| `家にあるものだけで、今日の献立が決まる` | 19 | 「だけで」を強めたいとき。少し説明的 |
| `今日の晩ごはん、家にあるもので` | 15 | 短さ優先。「決まる」が消えて結果が弱い |
| `帰り道で、今日の晩ごはんが決まる` | 16 | 「帰宅途中50.4%」に最も忠実で刺さるが、**冷蔵庫アプリだと分からない**。広告見出し向け |

**却下案（比較検討層向けなので、ここには置かない）**

| 案 | 却下理由 |
|---|---|
| `分量を変えない。出典を残すAI` | **前回の採用案**。初見に通じない（大翔「意味がわかんない」）。→ 説明文の本文へ移動 |
| `AIが勝手に分量を変えないレシピ` | 同上。否定形＋前提知識が要る |
| `読めない分量は読めないと書く` | 同上。刺さる層が狭い |
| `冷蔵庫の在庫だけで、人数分ぴったり` | クラシル／DELISH の人数変更難民向け。悩みが具体的すぎて初見には通じない |

## 4. 説明文

### プロモーションテキスト（170字以内・審査なしで差し替え可）

**初見向け**。「もっと見る」を押す前に読まれる場所なので、悩みから入る。

```
今日の晩ごはん、まだ決まっていませんか。CookSyncは、いま家にあるものを3つ入れるだけで、それだけで作れる料理を3案出します。足りない材料は「1パック」など店で買える単位で買い物リストへ。作ったら、使った分だけ冷蔵庫が減ります。登録もログインも要りません。
```

（131字）

### 説明文（4,000字以内）

**構成**：冒頭2ブロック＝初見向け（悩み→どう解決するか）／3ブロック目以降＝比較検討向け（差別化）。
App Store の説明文は最初の3行しか折りたたまれずに見えないので、**差別化は必ず「もっと見る」の内側**に置く。

```
■ 今日なに作るか、家にあるもので決まる。

夕食でいちばん面倒なのは、作ることより「今日なに作るか」を決めることです。
CookSyncは、いま家にあるものを3つ入れるところから始まります。
冷蔵庫を全部登録する必要はありません。

・冷蔵庫を1枚撮れば、写っている食材をまとめて読み取ります
・よく買うものはタップだけで入ります
・3つ入った時点で、それだけで作れる料理を3案出します


■ 買い物も、作ったあとも、つながっています。

・足りない材料は「1パック」「1束」など店で買える単位で買い物リストへ
・買ったものにチェックを入れると、そのまま冷蔵庫に入ります
・レシピの「作った」を押すと、使った分だけ冷蔵庫が減ります（取り消せます）
・賞味期限が近い食材は、選んだ時刻に1日1通だけまとめてお知らせします

登録もログインもなしで使えます。アカウントを作ると、別の端末でも同じ冷蔵庫が開けます。


■ AIが勝手に、分量を変えない。

レシピをAIに読み取らせると、はっきり読めなかった分量まで、それらしい数字で埋めてしまうことがあります。
「砂糖 大さじ1」が「小さじ1」に変わっていても、作りはじめてからでは戻せません。
CookSyncは、分からなかったことを分からないまま出します。

・読み取れなかった材料は「⚠ 分量が読み取れなかった材料：〇〇」と名前を挙げて警告します
・どれくらい自信があるかを3段階で表示します（低いときは「分量は必ず元の動画・写真で確認してください」と書きます）
・参考にしたページのURLを必ず残します。出典が付かなかったときも見出しを消さず「参考ページが記録されていません」と正直に書きます

取り込んだレシピは確認画面を挟んでから保存します。
材料・手順・読み取れなかった箇所を見て、納得してから残せます。


■ 「冷蔵庫にあるものだけ」を、本当に守る。

冷蔵庫に食材が入っていれば、献立提案は最初から「在庫だけで作る」で始まります。
塩・しょうゆなどの基本調味料以外は、冷蔵庫に無い食材を使わせません。

・買い足したい日は「買い物してもOK」に1タップで切り替えられます
・期限が近い食材から優先して使う献立を出します


■ 手順の文章の中の分量まで、書き換わる。

1〜4人分を選ぶと、材料表だけでなく手順の文章とkcalまで換算します。

・「大さじ1」「80〜90g」「1と1/2個」も、読める形のまま換算
・手順の「5分煮る」などの時間や温度は換算しません（分量だけを直します）
・増やすときは「調味料は7〜8割から入れて味を見て」という注意も表示します


■ レシピの入れ方は、3つ。

1. AIに提案してもらう
   冷蔵庫の食材と、気分・調理時間・人数から3案。期限が近い食材から優先して使います。

2. 動画のURLから
   YouTube・TikTokの料理動画を貼るだけ。概要欄と字幕から材料と手順を書き起こします。

3. 写真から
   レシピ本のページ、SNSのスクリーンショット、手書きメモを4枚まで。
   順番がバラバラでも、調理の進み方から並べ直します。

どの入れ方でも、読み取れなかった分量と出典の扱いは同じです。


■ そのほかの機能

・写真で在庫登録 — 冷蔵庫や食材を撮るだけ。食材名を読み取り、賞味期限とカテゴリを自動で推定します
・賞味期限の見える化 — 近い・そろそろ・余裕を色分け。期限が近い順に並びます
・賞味期限のお知らせ — 何日前・何時に知らせるかを選べます。当日と期限切れは必ず知らせます。対象が0件の日は送りません
・調理タイマー — 手順の「○分」を読み取り、ワンタップで使えるタイマーに。複数同時に動かせます。アプリを閉じていても完了を通知します
・好みの学習 — 星評価で提案が自分仕様に。直近に作った料理は自動で避けます
・余った食材の保存方法 — 使い切れなかった分の保存のしかたをレシピごとに表示します


■ 料金

基本無料です。アプリ内課金・広告はありません。
原価のかかるAI機能だけ、週ごとの利用回数に上限があります。
（AIレシピ探索 2回／写真で在庫登録 6回／写真・動画からレシピ 2回。毎週月曜0時にリセット）
人数の換算、在庫管理、買い物リスト、調理タイマー、期限のお知らせはAIを使わないため、回数制限はありません。
```

## 5. スクリーンショットで見せる順番（案）

**1〜2枚目＝初見向け**（悩み→最初の一歩）、**3枚目以降＝比較検討向け**（差別化）。
検索結果の一覧では1〜3枚目しか見えないので、**1枚目に「分量」を出さない**（前案からの変更点）。

1. **ホーム or 冷蔵庫（「あと3つで今日の献立を出せます」が出ている状態）**
   キャプション：「今日なに作るか、家にあるもので決まる」
2. **献立提案の結果（3案が並んでいる状態）**
   キャプション：「家にあるものを3つ入れるだけ」
3. **買い物リスト**（1パック等の単位）
   キャプション：「足りない分だけ、店で買える単位で」
4. **取り込み確認画面**（`⚠ 分量が読み取れなかった材料：…` が出ている状態）
   キャプション：「AIが勝手に、分量を変えない」
5. **レシピ詳細の人数セレクタ＋手順**（2人分→4人分で手順文の数値が変わっているのが分かる並び）
   キャプション：「手順の中の分量まで書き換わる」
6. **レシピ詳細の「参考にしたページ」**（URLリンクが並んでいる状態）
   キャプション：「どこから来たレシピか、必ず残る」
7. **冷蔵庫リスト**（期限の色分け）
   キャプション：「期限が近い順に並ぶ」

## 6. まだ言えないこと（実装が足りない主張）

提出テキストに**書かないこと**。実装されたらこの節から上へ移す。

| 言いたいが言えない | 理由 |
|---|---|
| レシートを撮るだけで在庫登録 | レシート読み取りは未実装（冷蔵庫写真からの食材認識はあるが、レシートに特化した処理は無い） |
| 何人分でも対応 | 人数セレクタは **1〜4人分** の4択（`RecipeDetail.tsx` L567）。「何人分でも」は誇張 |
| 献立提案は必ず在庫だけで始まる | **冷蔵庫が0件のときは「買い物してもOK」で始まる**（`MealWizard.tsx` L137-139）。「食材が入っていれば」の限定が要る |
| 出典のないレシピは絶対に出ない | AIへの指示（プロンプト）であって、サーバー側で弾いてはいない。だから「出典が空でも隠さず書く」までしか言えない |
| 分量が絶対に正しい | 保証していない。「読めなかったことを隠さない」「出典を残して確認できる」まで |
| 栄養計算・PFCバランス | kcal の換算のみ。栄養素の計算は無い |
| 家族・複数人で在庫を共有 | 共有機能は無い（データは1uidに紐づく） |
| 献立の週間プラン自動作成 | 最大で「今日＋翌日／4食」まで（`mealplan.ts` の `slotsForTiming`）。週次の自動プランニングは無い |
